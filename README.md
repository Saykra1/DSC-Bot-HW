# DSC-Bot-HW

Telegram-бот и мини апп для «Месяца бота» DSC Lab: участники сдают домашки в виде Jupyter-ноутбуков,
бот сверяет их с эталонным решением и присылает оценку и короткий отзыв по коду.

## Как это работает

1. Организатор создаёт задание и загружает **два файла**: шаблон для участников и эталонное решение.
2. Бот находит в шаблоне ячейки-задания (см. ниже) и сопоставляет их с ячейками эталона.
3. Участник скачивает шаблон, дописывает код и присылает свой `.ipynb` боту или через мини апп.
4. Для каждого задания:
   - ячейка не тронута → «не выполнено», 0 баллов (без запроса к LLM);
   - код совпадает с эталоном → 10 баллов (без запроса к LLM);
   - иначе код уходит в LLM вместе с условием и эталоном. Один запрос на всю работу.
5. Участник получает в чат оценку по каждому заданию (0–10), отзыв и до трёх советов.

Код участников **не запускается** на сервере: проверка идёт только сравнением с эталоном через LLM.

## Как оформлять ноутбуки

- **Шаблон** — ноутбук для участников. Ячейка считается заданием, если в ней есть строка `...`
  или комментарий «Пишите ваш код» / «Ваш код здесь» / «Your code here» (список настраивается через `TASK_MARKERS`).
- **Эталон** — тот же ноутбук, где в ячейках-заданиях написано решение. Остальные ячейки должны совпадать с шаблоном:
  по ним бот понимает, где какое задание.
- Условие задания — это комментарии в ячейке-задании и ближайшая markdown-ячейка над ней. Заголовок этапа
  (`### Этап 3: ...`) становится названием задания.
- Участник может добавлять свои ячейки рядом с заданием, они тоже попадут в проверку.
- Между двумя заданиями лучше оставлять хотя бы одну неизменяемую ячейку: так сопоставление надёжнее.

После загрузки бот показывает, какие задания нашёл, и предупреждает, если в эталоне для какого-то задания нет решения.
Пример пары файлов: `tests/fixtures/template.ipynb` и `tests/fixtures/reference.ipynb`.

## Запуск локально

Нужен Python 3.11+ (на Windows пакет `tzdata` из requirements обязателен).

```bash
git clone https://github.com/Saykra1/DSC-Bot-HW.git
cd DSC-Bot-HW
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env             # Windows: copy .env.example .env
```

Заполни `.env`:

| Переменная | Где взять |
|---|---|
| `BOT_TOKEN` | @BotFather → `/newbot` (или `/mybots` → бот → API Token) |
| `ADMIN_IDS` | свой ID и ID других организаторов через запятую, узнать у @userinfobot |
| `LLM_API_KEY` | ключ провайдера LLM, см. ниже |
| `LLM_BASE_URL`, `LLM_MODEL` | провайдер и модель, примеры в `.env.example` |

Запуск:

```bash
python -m app.main
```

Бот сразу работает через polling: напиши ему `/start`. Организаторам доступна команда `/admin`.

### Ключ для LLM (бесплатно)

Подойдёт любой OpenAI-совместимый API. Самый простой вариант — **OpenRouter**:

1. Зарегистрируйся на https://openrouter.ai.
2. Keys → Create Key, скопируй ключ в `LLM_API_KEY`.
3. Выбери бесплатную модель на https://openrouter.ai/models?q=free (у них в названии `:free`) и впиши её в `LLM_MODEL`.

У бесплатных моделей есть лимиты на число запросов в минуту и в день (смотри на сайте провайдера).
Одна проверка = один запрос, плюс при ошибках клиент сам повторяет запрос несколько раз.
Если модель отвечает ошибкой про `response_format`, бот сам переключится на обычный режим, но можно сразу
поставить `LLM_JSON_MODE=false`.

### Мини апп (нужен HTTPS)

Telegram открывает мини аппы только по HTTPS. Без хостинга проще всего поднять бесплатный туннель
[cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/):

```bash
cloudflared tunnel --url http://localhost:8080
```

Он напечатает адрес вида `https://something.trycloudflare.com`. Впиши его в `WEBAPP_URL` в `.env` и перезапусти бота.
Бот сам добавит кнопку «Домашки» в меню чата и кнопку «Открыть мини апп» в `/start`.

Если в выводе cloudflared есть `Allow outbound ... on port 7844`, значит сеть блокирует его порт.
Тогда подойдёт туннель через обычные порты:

```bash
# localhost.run: ничего ставить не нужно, ssh есть в Windows 10+
ssh -R 80:localhost:8080 nokey@localhost.run
# или ngrok (нужна регистрация на ngrok.com)
ngrok http 8080
```

Адрес такого туннеля меняется при каждом перезапуске, тогда нужно обновить `WEBAPP_URL`.
Постоянный адрес даёт, например, бесплатный статический домен ngrok или именованный туннель Cloudflare.

Всё, что умеет мини апп, доступно и командами бота, так что без туннеля тоже можно работать.

### Если бот не подключается к Telegram

Ошибка `Cannot connect to host api.telegram.org:443` значит, что Telegram API недоступен из этой сети
(так бывает в сетях вузов и у некоторых провайдеров). Варианты: другая сеть (например, раздача с телефона), VPN
или прокси в `.env`: `BOT_PROXY=socks5://host:port` (или `http://...`).

## Команды бота

Участникам:
- `/start`, `/help` — как сдавать;
- `/tasks` — задания: скачать шаблон, сдать работу, посмотреть попытки;
- `/my` — мои сдачи и отзывы;
- можно просто прислать `.ipynb`, бот спросит, к какому заданию его отнести.

Организаторам:
- `/new` — создать задание (название → описание → шаблон → эталон → лимит попыток и дедлайн);
- `/admin` — список заданий: сдачи, выгрузка CSV с лучшими результатами, открыть/закрыть приём;
- `/sub <id>` — отзыв и файл конкретной сдачи;
- `/recheck <id>` — перепроверить сдачу (например, после ошибки LLM).

## Правила сдачи

- Лимит попыток на задание (по умолчанию 3, задаётся при создании). Засчитывается лучшая.
- Если проверка упала (например, у модели кончился лимит), попытка не сгорает: участник получает сообщение,
  организаторы получают уведомление с командой `/recheck`.
- Пока предыдущая работа проверяется, новую по тому же заданию отправить нельзя.
- После дедлайна или закрытия приёма работы не принимаются. Для организаторов лимита попыток нет.

## Структура

```
app/
  main.py        точка входа: бот + очередь проверки + веб-сервер в одном процессе
  config.py      настройки из .env
  notebook.py    разбор .ipynb, поиск заданий, сопоставление ячеек
  checker.py     проверка работы и промпт для LLM
  llm.py         клиент OpenAI-совместимого API
  service.py     задания, сдачи, лимиты, очередь
  bot.py         хендлеры Telegram-бота (aiogram 3)
  web.py         API мини аппа (FastAPI), проверка подписи Telegram initData
  static/        страница мини аппа
tests/           тесты (pytest)
```

Данные (SQLite и загруженные файлы) лежат в папке `data/`.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Для отладки мини аппа в обычном браузере можно задать `DEV_USER_ID=<твой ID>` и открыть http://localhost:8080.
Не оставляй эту переменную при реальном запуске: с ней любой, кто откроет адрес, войдёт под этим пользователем.
