# Развёртывание на сервере

Инструкция для VPS (проверено под Timeweb Cloud NL-50: 2 vCPU, 4 ГБ, 50 ГБ NVMe, IPv4, Нидерланды).
На сервере работают два контейнера:

- `bot` — бот, очередь проверки и веб мини аппа (один процесс, как при локальном запуске);
- `caddy` — HTTPS: сам получает и продлевает сертификат Let's Encrypt и проксирует запросы в `bot`.

Оба перезапускаются сами при падении и после перезагрузки сервера (`restart: unless-stopped`).
Данные (SQLite и файлы) лежат в `/opt/dsc-bot/data`, бэкапы — в `/opt/dsc-bot/backups`, каждый день в 04:00 МСК.

## 1. Заказ сервера

- **ОС: Ubuntu 24.04 LTS** (чистая, без панелей и готовых приложений).
- Регион: Нидерланды. Из России api.telegram.org и OpenRouter бывают недоступны, из NL работают без прокси.
- Публичный IPv4 нужен (для HTTPS и чтобы Telegram открывал мини апп).
- **SSH-ключ** лучше добавить прямо при заказе (поле «SSH-ключ»), тогда пароль не понадобится.

### Как сделать SSH-ключ (один раз, на своём компьютере)

Windows 10/11 (PowerShell), macOS и Linux (терминал) — одна и та же команда:

```bash
ssh-keygen -t ed25519 -C "dsc-bot"
```

На все вопросы можно нажать Enter. Публичный ключ (его и вставлять в Timeweb):

```bash
# Windows
type $env:USERPROFILE\.ssh\id_ed25519.pub
# macOS / Linux
cat ~/.ssh/id_ed25519.pub
```

Строку `ssh-ed25519 AAAA... dsc-bot` целиком вставь в панели Timeweb: «SSH-ключи» → «Добавить» (или при заказе сервера).
Файл без `.pub` — приватный ключ, его никому не отправляй.

Если сервер уже создан без ключа: зайди по паролю из письма и выполни
`mkdir -p ~/.ssh && echo "ssh-ed25519 AAAA... dsc-bot" >> ~/.ssh/authorized_keys`.

## 2. Первичная настройка

Подключись к серверу (IP — в панели Timeweb):

```bash
ssh root@IP_СЕРВЕРА
```

Дальше всё на сервере. `BRANCH` — ветка, с которой запускаться: `main`, когда все PR влиты, а до этого — ветка с деплоем.

```bash
BRANCH=main
apt-get update && apt-get install -y git
git clone --branch "$BRANCH" https://github.com/Saykra1/DSC-Bot-HW.git /opt/dsc-bot
bash /opt/dsc-bot/deploy/setup-server.sh "$BRANCH"
```

Скрипт (5–10 минут) обновит систему, поставит Docker, включит файрвол (открыты только 22, 80, 443), fail2ban,
автообновления безопасности, подкачку 2 ГБ, ежедневный бэкап и создаст `/opt/dsc-bot/.env`.
Если ключ SSH уже на сервере, вход по паролю будет отключён.

## 3. Настройки

```bash
nano /opt/dsc-bot/.env
```

Обязательно заполнить:

| Переменная | Что писать |
|---|---|
| `BOT_TOKEN` | токен из @BotFather |
| `ADMIN_IDS` | Telegram ID организаторов через запятую (@userinfobot) |
| `LLM_API_KEY` | ключ OpenRouter (https://openrouter.ai → Keys) |
| `LLM_MODEL` | 2–3 модели через запятую: первая основная, остальные запасные |
| `CHECK_CONCURRENCY` | `5`–`10` для платного ключа и 100+ участников, `1`–`2` для бесплатных моделей |
| `DOMAIN`, `WEBAPP_URL` | скрипт уже вписал `IP-С-ДЕФИСАМИ.sslip.io` и `https://...`, менять не обязательно |
| `BACKUP_CHAT_ID` | по желанию: свой Telegram ID, чтобы бот каждый день присылал архив бэкапа |
| `DEV_USER_ID` | **оставить пустым** |

`BOT_PROXY` на сервере в Нидерландах не нужен. Сохранить в nano: `Ctrl+O`, Enter, `Ctrl+X`.

**Свой домен вместо sslip.io** (по желанию): в DNS домена создай A-запись `bot.example.ru → IP_СЕРВЕРА`,
впиши `DOMAIN=bot.example.ru` и `WEBAPP_URL=https://bot.example.ru` и перезапусти (`docker compose up -d`).
sslip.io — бесплатный адрес, который сам указывает на IP из своего имени; для старта его хватает.

## 4. Запуск

> Если бот уже запущен у тебя на компьютере, **останови его**: два экземпляра с одним токеном мешают друг другу
> (в логе будет `TelegramConflictError`).

```bash
cd /opt/dsc-bot
docker compose up -d --build
docker compose logs -f bot        # выход из логов: Ctrl+C, бот продолжит работать
```

В логе должно быть `Бот @... подключён к Telegram`. Проверь:

1. В браузере открывается `https://ДОМЕН/health` → `{"ok":true}` (первый запуск Caddy получает сертификат, до минуты).
2. Боту в Telegram — `/start`, кнопка «Открыть мини апп» открывает мини апп.
3. Сдай тестовый ноутбук: проверка проходит, в логе видно, какой моделью.

### Перенос данных с компьютера

Если локально уже есть задания и сдачи, перенеси папку `data` (бот на сервере в этот момент остановлен):

```bash
# на сервере
cd /opt/dsc-bot && docker compose stop bot
# на своём компьютере, из папки проекта
scp -r data/* root@IP_СЕРВЕРА:/opt/dsc-bot/data/
# снова на сервере
chown -R 1000:1000 /opt/dsc-bot/data && docker compose start bot
```

Если в локальной `data` есть `webapp_url.txt` (адрес туннеля из `/webapp`), удали его на сервере:
он важнее `WEBAPP_URL` и указывает на старый туннель.

## Повседневное

Все команды — из `/opt/dsc-bot`.

| Что | Команда |
|---|---|
| Обновить до свежего кода (с бэкапом перед этим) | `./deploy/update.sh` |
| Логи | `docker compose logs -f bot` (последние 200 строк: `--tail 200`) |
| Статус | `docker compose ps` (должно быть `healthy`) |
| Перезапустить (например, после правки `.env`) | `docker compose up -d` |
| Остановить / запустить | `docker compose stop` / `docker compose start` |
| Бэкап вручную | `./deploy/backup.sh` |
| Восстановить из бэкапа | `./deploy/restore.sh backups/dsc-bot_ДАТА.tar.gz` |
| Место на диске | `df -h /` и `du -sh data backups` |

После `git pull` на другую ветку: `git fetch && git checkout ВЕТКА && ./deploy/update.sh`.

## Бэкапы

- Каждый день в 04:00 МСК `deploy/backup.sh` делает согласованный снимок базы (без остановки бота) и архивирует
  его вместе с файлами заданий и хакатонов в `backups/`. Хранятся 14 дней, лог — `/var/log/dsc-bot-backup.log`.
- Бэкап на том же сервере не спасёт, если пропадёт сам сервер. Поэтому включи хотя бы одно из:
  - `BACKUP_CHAT_ID` в `.env` — бот присылает архив в Telegram (до 49 МБ, лимит Bot API);
  - автоматические бэкапы сервера в панели Timeweb (платная опция, снимок всего диска).
- Скачать бэкап на компьютер: `scp root@IP_СЕРВЕРА:/opt/dsc-bot/backups/dsc-bot_ДАТА.tar.gz .`

`restore.sh` не удаляет текущие данные, а переименовывает папку в `data.before-restore-ВРЕМЯ`.

## Если что-то не так

- **`https://ДОМЕН` не открывается.** `docker compose logs caddy`. Частые причины: A-запись своего домена ещё
  не обновилась (до часа) или опечатка в `DOMAIN`. Порты 80 и 443 должны быть открыты (`ufw status`).
- **Бот не отвечает.** `docker compose logs --tail 100 bot`: неверный токен, ошибка в `.env` (бот пишет, какая
  переменная) или `TelegramConflictError` (запущен второй экземпляр).
- **Проверки падают.** В логе ошибка от LLM: кончились кредиты OpenRouter, модель убрали или лимит запросов.
  Уменьши `CHECK_CONCURRENCY` или поменяй модели, затем `docker compose up -d` и `/recheck <id>` для упавших сдач.
- **Мини апп показывает старую версию.** Закрой и открой мини апп заново; после `update.sh` версия файлов меняется.
