# Нагрузочный тест

Проверяет, выдержит ли бот ~100 участников одновременно: открытие мини аппа, тест, сдача ноутбука
и ожидание проверки (мини апп опрашивает статус раз в 4 с, а если впереди больше 10 работ — раз в 15 с).

| Файл | Что это |
|---|---|
| `loadtest.py` | Генератор нагрузки: N выдуманных участников с подписанным initData. Создаёт тестовое задание и сдачи, поэтому направлять его можно только на **отдельный тестовый экземпляр**. |
| `fake_llm.py` | Фейковая OpenAI-совместимая модель: задержка ответа и лимит 20 запросов в минуту, при превышении 429 как у OpenRouter (без `Retry-After`). |
| `server-check.sh` | Безопасный запуск на боевом сервере: копия базы, отдельный контейнер без сети, отчёт, уборка. |

## На боевом сервере

```bash
cd /opt/dsc-bot && ./loadtest/server-check.sh
# можно поменять: USERS=150 DURATION=120 ./loadtest/server-check.sh
```

Скрипт не трогает настоящую базу и боевой контейнер: тестовый бот работает на копии базы в контейнере
с `--network none`, то есть физически не может написать участникам в Telegram или потратить лимит OpenRouter.
Копия удаляется в конце. Процессор 2–3 минуты делится с боевым ботом, поэтому лучше запускать, когда участников мало.
В конце печатается, как во время теста отвечал настоящий сайт.

Как читать отчёт: `ВЕРДИКТ: OK` — ошибок меньше 1%, 95% запросов быстрее 1 с, ни одна проверка не упала.
Строка `Бот: CPU ... память ...` показывает запас: если CPU p95 близко к 100% — сервер на пределе.

## Локально (на своём компьютере)

```bash
pip install -r requirements.txt
python loadtest/fake_llm.py --latency 20-40 --rpm 20 &
BOT_TOKEN= ADMIN_IDS=900000001 DATA_DIR=/tmp/lt LLM_BASE_URL=http://127.0.0.1:9999/v1 \
  LLM_MODEL=fake-a:free,fake-b:free LLM_API_KEY=x CHECK_CONCURRENCY=6 python -m app.main &
python loadtest/loadtest.py --users 100 --duration 120 --drain 480 --pid $!
```

Чтобы ограничить бота как на сервере, запусти его в Docker с `--cpus 1 --memory 2g`.
Сценарий «все сдают перед дедлайном»: добавь `--spike`.

## Результаты (9 ноября 2026, 1 ядро Xeon 2,1 ГГц / 2 ГБ, как у сервера)

| Сценарий | Итог |
|---|---|
| 100 участников ходят по мини аппу 2 мин и сдают ноутбук | ~80 запросов/с, 0 ошибок, p95 75 мс, CPU ~31%, память ~240 МБ |
| 100 сдач почти одновременно, модель с лимитом 20 запросов/мин, **до исправлений** | 41 из 100 проверок упали с ошибкой («Ни одна модель не ответила») из-за 429 |
| То же **после исправлений** | 100 из 100 проверено, 0 ответов 429, вся очередь за ~5,5 мин |
| Стресс: 300 участников, запросы в 3 раза чаще | до: 238 запросов/с, p95 1,5 с. После: 323 запроса/с, p95 0,6 с, 0 ошибок |

Узкое место не сервер, а модель: бесплатные модели OpenRouter — 20 запросов в минуту и **50 запросов в день**
(1000 в день, если хоть раз пополнить баланс на $10). Одна проверка ноутбука = один запрос.
